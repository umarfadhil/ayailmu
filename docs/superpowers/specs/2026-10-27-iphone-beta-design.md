# AyaIlmu native iPhone beta

The owner wants a usable AyaIlmu beta on iPhone and Android. Parent explicitly directs local implementation, not another inventory-only pass. Existing direction is SwiftUI with the same Kotlin learning core; this design follows it. Android checkpoint ad8bd595 stays on its original worktree/branch. iOS work is isolated on feature/umar-ios-beta-20261027.

The first runnable milestone is a real SwiftUI account app, backed by the existing GoTrue and Go owner contracts, with Keychain session storage. It includes create account, confirm email, sign in, recovery/reset, native restore/refresh and logout. No Google button appears because no OAuth setup exists. No credentials are embedded. Tests use synthetic fixtures; live checks may call only health and unauthenticated protected routes because AyaIlmu's approved mail allocation is exhausted.

The product is not the reference Expo prototype. A SwiftUI shell avoids replacing Android, while shared-core integration later preserves scoring/mastery parity instead of inventing a Swift mastery algorithm. Account/network code is a small Swift package with exact wire DTOs, injectable transport/vault for tests and standard URLSession/Security APIs. No third-party runtime dependency or paid service is needed for this slice.

Normal HTTPS uses system trust. An explicit Debug-only private-owner-QA build may trust the designated public CA only for https://localhost:58443, with normal hostname verification, exact DER fingerprint validation and no OS trust changes. Release builds cannot activate that trust path. Config values and consent/declaration versions are supplied from the authoritative runtime handoff; no policy text or production readiness is invented.

Session install requires a confirmed provider user and backend /v1/account activation using the existing adult declaration. Restore checks the provider user, refreshes only401 or403 bad_jwt, requires the same subject and backend account, then persists. Logout fences pending work, clears the app vault before reporting local sign-out and attempts provider local logout. Session and error descriptions are redacted. Redirects never forward bearer/password bodies. An unavailable endpoint or failed storage operation produces an actionable error, never a fake success.

Later milestones add adult self-profile selection and account/learner-namespaced local persistence, shared-core answer/scoring parity, explicit per-learner consent, immutable answer events and cursor-based pull/replay. The existing adult math Unit01 (18 entries, one lesson screen) is a concrete candidate, not approved content. All3,162 source items remain draft; no test fixture becomes a beta lesson. No UI may record progress without an actual permitted lesson and durable write.

Xcode27.1 at /Applications/Xcode-27.1.app is used through task-local DEVELOPER_DIR. The existing iPhone Duo simulator belongs to AyaFasih and is untouched; AyaIlmu gets its own simulator. Simulator builds use CODE_SIGNING_ALLOWED=NO. Apple team/bundle ownership, provisioning, TestFlight upload/invite and public endpoint setup remain separately gated. No new grants, keys, account login or paid services are part of this implementation.
