# Temporary owner-only Android beta

The `ownerRemote` debug flavor is separate from `prod`, localhost-pinned `normalQa`, and `syncLab`. It uses normal account/backend code with system-only HTTPS trust. Its package suffix is derived from its public origin, isolating Keystore, Room and preferences from other environments. No private CA, normal-QA arithmetic fixture or synthetic sync UI is included. Production auth approval stays off by default.

Build only from an approved, current runtime handoff. Supply `umar.ownerRemote.buildEnabled=true`, `umar.ownerRemote.approved=true`, `publicOrigin`, `expiresAtUtc`, `ownerDeclarationVersion`, `syncPolicyVersion`, and `registrySourceCommit` as the corresponding `umar.ownerRemote.*` Gradle properties. The origin must be a canonical temporary trycloudflare HTTPS origin with no path, port, credentials, query or fragment. The handoff expiry must still be in the future and within36 hours. Exact private-owner policy and frozen-registry versions are enforced. Then run `:app:assembleOwnerRemoteDebug :app:lintOwnerRemoteDebug`. No ownerRemote release variant exists. Do not reuse production approval inputs or retarget `normalQa`.

The Android adapter has no local JWT issuer setting. It uses the single public API/Auth origin while GoTrue/backend retain their existing issuer and verify tokens. Do not change the provider issuer or invent a new client issuer property.

Only the already-confirmed invited adult owner may sign in. Registration, confirmation, resend, recovery and password changes are hidden and blocked before the HTTP adapter in this profile; the gateway separately denies those routes. Ordinary confirmed login, refresh, user verification and local logout use the existing implementations. No credential belongs in the build or repository. Gateway refresh state is memory-only, so a gateway restart may require password sign-in again. The server expires the connection at its approved deadline even if the APK remains installed.

The ordinary production draft-content filter remains active. The runtime's frozen catalog has zero approved curriculum items: no lessons or lesson-sync success can be claimed. Content review/version/proof activation is a separate decision. This profile is for the named owner only, not a general beta or store release. It does not enable child profiles or automatic uploads; per-learner sync still requires explicit consent. Keep the Mac awake and online during the temporary route.

Before distribution, inspect the built APK's DEX config, identity, signature, network-security XML and assets; install it on the designated test device; verify actual HTTPS/protected routes and the reachable sign-in-only UI. Report owner login and lesson checks separately from public health and unit tests. No public upload, endpoint change, signing-key generation, mail request, account reset or store submission is part of building this profile.
