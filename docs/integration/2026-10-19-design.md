# Native/backend integration — synthetic vertical slice

Base: latest fetched native main `815e30f` + pushed backend `e490842`. Branch
`feature/umar-native-integration-20261019`; no merge/push or changes to Amar's app.

## Scope

A separate Android **syncLab** flavor (`.synclab` application ID) connects the real
native session engine to the existing API. Normal demo/prod entry points retain
on-device behavior, with no auth SDK or networking permission added to production.
The lab creates fabricated ADULT learners only; it never enumerates or links normal
app profiles. Only the existing Arabic DEMO pack emits `synthetic:true` native
answers, so it is the first learning track. Child learning and other tracks remain
blocked from sync until reviewed synthetic content/eligibility contracts exist.

Use AppAuth Android, system browser, code + S256 PKCE, fresh login and in-memory
access tokens. No WebView, custom crypto, password grant in the app, or persisted
tokens. Existing Arabic 18+ trial consent UI remains separate from explicit
`synthetic-sync-v1` sync opt-in. All identities, profiles and answers in tests are
fabricated. No real-data switch is introduced.

## Components

- `core:sync` (pure Kotlin): existing API DTOs/HTTP adapter; durable atomic journal;
  owner/learner binding; byte-frozen outbox; explicit consent state; per-learner
  remote history/cursor; session generation fences; recovery/protocol checks.
- syncLab Android shell: AppAuth sign-in, synthetic profile create/select, opt-in
  and revoke, offline native Arabic session, manual sync and synced progress panel.
  Reuses existing `ConsentRoute`/`SessionRoute`; does not change scoring/mastery.
- Room bridge reads saved **payload strings** by profile after the original native
  answer/snapshot transaction commits. Only allowlisted synthetic lab profiles are
  observed. Pre-opt-in/off-period answers are excluded; prior opted-in pending
  answers remain frozen for retry. Normal local answers are never rewritten.
- Remote history is kept separately. A read-only synced lane uses the unchanged
  native `SkillProjector` only after matching local pack/rules hashes and versions;
  it does not overwrite Room answers or the native local mastery lane.

## Invariants and recovery

Owner identity comes from the authenticated `/v1/account` response, never a decoded
unverified token. Bindings, queued bytes, consents and cursors are scoped by owner
AND learner. Login to another account cannot send, display or acknowledge the prior
owner's data. Logout fences late responses, clears tokens/active selection and
returns to the lab hub. An already-authorized in-flight request may reach its own
owner's server; its late result cannot affect a new session.

Opt-in defaults off. Establish server consent before enabling local uploads. Turning
it off disables uploads immediately and durably records a pending withdrawal;
offline withdrawal is retried for the same owner before any future upload. A remote
403 consent failure disables local sync and hides the remote lane until explicit
regrant. 401/session expiry retains frozen pending data and requires re-login.
Offline learning writes Room normally; no successful network request is required.

Server receipts must match the entire sent batch before local acknowledgement.
Cursor/history commits are atomic; failed pulls leave the old cursor. Duplicate
retry preserves exact payload strings. Conflicts/malformed responses fail closed,
never discard an answer. New opt-in baselines existing answer IDs; it never silently
backfills historical local records. Pack/rules SHA256 must match before uploading
or projecting remote history. Schema/API v1 remains unchanged unless tests show a
necessary additive extension.
